# Honest Model Evaluation

Generated by `evaluate_model.py` against the **already-committed** per-date hotspot
GeoJSONs (no Copernicus download required). This replaces the misleading
"mean score at catch locations" headline with presence/background discrimination
metrics that actually measure whether the map is useful.

> **Read this caveat first.** These numbers evaluate the *deployed* score grid, whose
> weights were tuned (Optuna) on these same catches. They are therefore an **optimistic
> in-sample bound**, not out-of-sample skill. A true estimate requires refitting the
> weights on a training fold and scoring only a held-out fold — which needs the full
> ocean-data pipeline (`marlin_data.py` + Copernicus). The leave-one-year-out AUC below
> is the honest stand-in available today; treat AUC as an upper bound.

## Blue marlin (49 catches with committed maps)

| Metric | Value | Meaning |
|---|---|---|
| Mean score incl. misses | **0.82** | The number to report (old headline dropped misses) |
| Miss rate (catch outside every zone) | 0/49 on committed maps* | *`validate_scoring.py` found 6/46 when re-scoring from NetCDF; the committed maps contain all catches |
| **AUC vs random ocean** | **0.93** | Strongly separates catch cells from random domain points |
| **AUC vs random in-zone point** | **0.78** | Within rendered zones, ranking one spot over another is only moderate |
| Best TSS | 0.74 @ 0.60 | — |
| Leave-one-year-out AUC | **0.91 ± 0.10** | Discrimination is stable across years, not driven by a few dates |

### Capture / lift curve (blue)

| Threshold | Catches kept | Domain area kept | Lift |
|---|---|---|---|
| ≥ 0.50 | 100% | 33% | ×3.0 |
| ≥ 0.70 | 86% | 14% | ×5.9 |
| ≥ 0.80 | 73% | 9% | ×8.0 |
| ≥ 0.90 | 27% | 3% | ×10.4 |

## What this tells us

1. **The model is genuinely skilful at the regional scale.** AUC ≈ 0.93 (in-sample) /
   0.91 (leave-one-year-out) means it reliably puts catches in higher-scoring water than
   random ocean, and the lift curve is operationally useful (≥0.80 keeps 73% of catches in
   9% of the area). This is better than the raw "mean 84%" suggested, and better than a
   purely pessimistic reading of the range-compression concern.

2. **Its weakness is fine-grained spot selection, not region selection.** AUC drops to
   0.78 when the background is restricted to points *already inside a rendered zone*. So the
   map answers "which part of the canyon?" well and "which exact drop?" only moderately —
   consistent with the day-relative normalisation and floor/boost stack flattening contrast
   inside hot zones.

3. **It is not blue-specific.** The same "blue marlin" grid scores **striped** marlin
   catches equally well (AUC 0.93 vs 0.93). The model is really a shared shelf-edge /
   Leeuwin-front **billfish** habitat index; it does not distinguish blue from striped
   habitat. This is expected given both species use the same front, and argues for either
   per-species thermal profiles or honest relabelling.

## How to run

```bash
python evaluate_model.py                       # blue marlin (default)
python evaluate_model.py --species ALL         # all billfish
python evaluate_model.py --species "STRIPED MARLIN"
python evaluate_model.py --bg-per-date 300 --seed 7 --json-out data/eval.json
```
